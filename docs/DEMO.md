# KISIV AI 演示指南

> 本文用于项目演示、录屏或向协作者介绍产品。当前为早期 MVP，请明确区分已实现能力与目标设计。

## 1. 演示目标

用一个可重复的安全事件示例，说明 KISIV AI 的核心思路：**事件进入 → 风险研判 → 受控响应（默认 dry-run）→ 审计记录**。

## 2. 启动本地项目

需要 Python 3.11+。在仓库根目录运行：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

打开 API 文档： http://127.0.0.1:8000/docs

## 3. 建议演示顺序

1. **介绍产品定位**：展示 [README](../README.md) 与[产品概览](../PRODUCT_OVERVIEW.md)。
2. **解释目标架构**：展示 [KISIV AI 架构图](images/kisiv-architecture.svg)，强调策略控制和结果验证。
3. **运行实际 API**：在 Swagger UI 中查看当前代码实际提供的端点，录入一条无敏感信息的测试事件。
4. **展示风险判断**：展示接口返回的规则研判字段，并解释它是当前实现的初步能力。
5. **展示模拟响应和审计**：只展示当前代码确实支持的 dry-run 行为及审计记录，不模拟或声称真实封禁、系统修改已经可用。
6. **说明下一步**：结合 [开发路线图](../ROADMAP.md) 介绍待实现模块。

## 4. 演示前检查

- [ ] 在干净环境中按 README 完成安装。
- [ ] 确认服务能启动，API 文档可打开。
- [ ] 运行测试：`pytest`。
- [ ] 使用虚构测试数据，不展示真实 IP、令牌、密钥、个人信息或生产日志。
- [ ] 逐项核对演示内容与当前代码，避免把路线图内容说成已交付功能。
- [ ] 录屏前关闭终端中的敏感环境变量和无关窗口。

## 5. 演示边界

当前 MVP 不是生产级安全产品。演示仅用于说明早期开发原型；真实环境部署前仍需独立安全评估、权限审查、测试和运维准备。
